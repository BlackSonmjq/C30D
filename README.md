# C30D 芒果机器人跑图重构

本工程从商家 R550 C30D 2.0 霍尔编码器版源码复制后独立修改，原始商家目录未修改。车头固定朝路线图上方，完成七沟蛇形巡航、右侧返程、对正出口和启动区停车。疏果机构仅预留暂停／继续接口。

**当前距离表是名义尺寸示例，尚未实车标定。`USER/nav_config.h` 的 `NAV_CALIBRATED` 默认是 `0`，因此当前固件不会按键起跑，但可显示和输出四路原始测距。填好现场标定值、检查整车通行余量后，再把它改为 `1` 并重新编译。** 本次没有连接串口、控制实车或烧录。

工程保留商家的外设和 FreeRTOS。C30D 2.x 识别 ICM20948 后，由 USB Host 接收手柄输入，统一交给底盘任务。经典 PS2 接口、航模 PWM、自动回充及旧串口底盘命令仍停用。

电机控制任务优先级4，IMU任务优先级3，串口诊断优先级2，避免串口发送与电机任务同优先级争用。商家存量 C/H 文件保留 GBK 编码；新导航文件和说明使用 UTF-8。

PWM 启动配置现已完整初始化。上电先将电机引脚保持低电平，配置定时器后保持强制无效，BOOT/READY 等待按键时不会开放 PWM。主工程 `NAV_CALIBRATED=0`。上电异常排查阶段留存的 CAL=1 验证快照在 `build/startup-cal1/`，详见上电异常排查说明。

## 手柄遥控与导航启动

- 上电进入导航待机。按下并松开手柄的 START（USB PS2）或 Menu（Xbox 兼容）可切换模式。接管会终止当前路线并关闭当周期的电机输出。手动模式在摇杆回中且车轮停稳后才接受拨杆。
- 导航待机时，按下并松开 PS2 的绿色面键（△）或 Xbox 兼容手柄的 Y 可启动。手柄和板载 USER 键共用导航的标定、IMU、测距、静止、使能和起跑距离检查。切回导航后，需要重新按一次启动键从 P01 起跑。导航运行中和手动模式下，手柄启动键无效。
- 左杆前后控制车体纵向，右杆左右控制横移，每轴上限 0.30 m/s，四轮目标限速 0.50 m/s。手动指令仍走原有电机控制回路和使能检查。200 ms 没有有效报告或收到断开事件时关闭驱动，保持手动模式，恢复后需重新回中。导航机构暂停握手期间仍由导航保持停车。
- 激光 CAN 和原有 48 通道 VOFA 两种模式均持续收发。手动时可看原始四向距离和 CAN 序号，导航滤波值和参考目标随导航状态更新。OLED 用 `MANUAL` 显示当前模式。
- USB 接收沿用商家已有的两种有线 PS2 报告和 Xbox 360 兼容报告。每个有效报告通过 `RemoteBoard_Publish(ly,rx,mode_pressed,nav_start_pressed)` 发布，断开时清除输入。USB Host 在调度器启动后运行，使用优先级 1，枚举错误由 USB Host 自己处理。实体键位和接收器兼容性待实车确认。

## 蓝牙查看激光与车辆状态

构建当前源码并烧录生成的 `OBJ/C30D_rebuild.hex` 后，USART2 以 9600、8N1 每约 300 ms 发送 48 个 float32，附 JustFloat 帧尾，共 196 字节。USART1 继续输出文本 CSV。蓝牙接收内容不进入运动控制。

断开手机 APP 后，双击 `build/vofa-align/WHEELTEC-BLE-VOFA-Align.exe`。VOFA 选择 JustFloat、UDP，本地端口 9000；远端若必填为 127.0.0.1:9001。CSV 自动保存在 EXE 旁的 `logs/`。完整步骤见 `BLE-VOFA使用说明.md`；双击 `build/vofa-align/自检.cmd` 可做不连接实车的离线检查。

四路原始值为 0～3，滤波为 4～7，当前参考目标为 8～11，顺序均为前/后/左/右。目标为 0 表示当前未使用，结合有效/参考掩码 12/13 判断。余下通道包含导航状态、点号、误差、速度命令、四轮目标/反馈/PWM、电池与使能等，见 `VOFA通道表.md`。

## 路线与控制

P01 从启动区前进到第1沟左入口；P02 到第1沟右出口。之后沿右侧前进到 P03，横移至 P04；沿左侧前进到 P05，横移至 P06；依次经过 P07～P14，完成七沟。P14 后沿右侧后退至 P15，横移至 P16 对正出口，后退至 P17 停车。

P15 与 P02、P16 与 P01 共用物理位置，点号包含任务阶段。返程经过其他入口不会重新进沟。程序只核对当前段的端点，不把相似沟内距离当成全场唯一定位；不会从一组相似读数随意跳到远处点号。

各段共用巡航、提前减速、低速比例校准、停稳确认和下一点切换逻辑。主方向按距离误差降速；另一轴仅小幅纠偏。车头用启动时的 IMU 航向作参考保持方向。到点必须所需两轴在容差内、航向合适、轮速接近零，再使用新测距帧确认。

左侧后激光主动不参与定位，即使它照到场外物体并返回正常值。沟内按前／后垄壁标定值居中；短垄缺口使用仍有正确近壁的另一路。入口／出口短过渡区由左右墙距确定横移进度，保持航向通过，不能用远墙读数拉偏车。

P17 使用本轮启动前静止采集的前激光距离。首尾出入口段忽略场外侧向读数；P01、P16 在场内对正。起跑摆位必须本来就使整车和机构完全位于启动区，才能复用该纵向停车位置。

## 停止与恢复

- 单路无效但其他参考足够时继续；当前所需参考不足时立即给零速目标制停，保留路线进度。
- CAN 快照自实际接收起达到 300 ms 失效。它是建议初值，要与底板实际周期核对；不把任务重读旧帧算成更新。
- 数据恢复后重建滤波窗口，并取得连续足够的新参考再继续；不要求已经在最终到点容差内才允许恢复。
- 一直无参考时一直等待。没有逐点失败次数锁死、自动绕行或全局跳沟流程。
- 用户再次按键、硬件失能、IMU 不可用会终止本轮。恢复测距或恢复使能不会自行启动；重新起跑需回到合法起跑位置并再次按键。
- 已知场内墙面太近时拦截继续靠近的动作；对应目标位于安全方向时，低速离开不被这一方向限制拦截。阈值必须包含击打机构外伸。
- 完成 P17 后保持停止，直到人工明确启动下一轮。

停车时先保留零速 PI 制停，停稳后按状态清一次内部 PWM／上次误差；正常变速、换向、位置修正期间不反复清 PI。机构暂停保持零速闭环。人工停止／失能直接关闭运动输出，准备下一轮时清理残留。

## 构建与验证

电脑上安装 ARM Compiler 5 后，可在本目录运行：

```powershell
python tools/build.py --toolchain 'G:/keil5/ARM/ARMCC/bin'
python tests/run_tests.py
```

构建脚本也支持环境变量 `ARMCC_BIN`；主机测试支持 `HOST_CC` 指定 GCC。它们不会连接下载器或烧录。Keil 用户可打开上述工程，选择已安装的 ARM Compiler 5 后执行 Build。若本机编译器安装位置不同，以本机设置为准。

输出在 `OBJ`：`C30D_rebuild.hex`、`.bin`、`.axf`、`.map`、构建日志和源码／产物哈希清单。脚本校验 HEX 校验和、与 BIN 的内容一致性、初始栈和复位向量。

主机测试使用名义场地模型和简化执行模型，检查全路线点序、短垄参考、左后场外回波、重复快照、断更、单路与多路失效、恢复、机构暂停、人工停止、硬件失能、PI 清理和加减速。**模拟完成不能证明实车精度、地毯通行或实际停车距离。**

## 机构接口

在将来的机构任务中包含 `nav_stm32.h`：

1. 调用 `Nav_RequestWorkPause()` 请求停车。
2. 等待 `Nav_WorkStopped()` 为真，再允许击打动作。
3. 机构回到适合行驶的状态后调用 `Nav_RequestWorkContinue()`。

继续时保留原目标点、路线阶段、航向基准和本轮起跑前距，重新验证测距后继续。当前没有约定外部串口／CAN 机构命令，不借用旧遥控协议。
