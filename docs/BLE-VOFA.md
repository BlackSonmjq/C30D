# 原蓝牙模块连接 VOFA

当前固件发送 31 通道，涵盖视觉 B/DX/G/REGION、有效帧数、对齐及完成流程阶段、S21C 后距和新鲜标志、横移及 IMU 指令、最近完成区域和累计完成次数，并追加 CH13～CH20 的目标角、实际角、误差、角速度、积分补偿、航向锁、姿态新鲜度和阻断位；CH21～CH32 为四轮目标、实际轮速及 PWM。通道定义见 [VOFA 输出](VOFA跑图诊断.md)。
运行时自动在 EXE 同目录的 `logs` 文件夹创建带时间戳的 CSV，包含电脑接收时间和实际收到的全部遥测字段，每帧刷新到磁盘。断线重连且通道数相同时仍写入本次文件；若烧录后通道数改变，工具结束，需重新启动以创建新表头。旧日志不改写。终端显示路径点、状态及故障原因变化。该文件可在程序运行期间读取分析；关闭旧版转发器后再运行新版，避免争用 BLE 和 UDP 9001。

## Windows 独立可执行文件

新版打包输出为 [WHEELTEC-BLE-VOFA-Wheel.exe](../../C30D-develop-EIDE/build/vofa-wheel/WHEELTEC-BLE-VOFA-Wheel.exe)。先关闭旧转发器，再启动 Wheel 版本或当前 Python 源码；旧版转发程序已清理，历史日志迁入新版目录的 logs/previous-imu，其中包含此前归档。
双击即可扫描、连接并转发，无需安装 Python 或 bleak；可单独复制 EXE 到其他 Windows x64 电脑。
运行前断开手机连接，开启电脑蓝牙。保留黑色状态窗口，Ctrl+C 停止。
VOFA 使用 JustFloat、UDP，本地端口 9000；远端如需填写为 127.0.0.1:9001。
命令行参数与 Python 版相同，`--self-test` 可检查内置依赖、分片重组及 UDP 收发，不连接实车。

当前实测手机可从 WHEELTEC-IOS 的 FFE0 / FFE1 Notify 收到字节。
底盘 USART2 串口侧保持 9600、8N1，当前输出 41 通道 JustFloat，共 168 字节。最小尝试间隔仍为 271 ms，结合 50 ms 调度，实际预计约 300 ms 一帧。
电脑通过 BLE 订阅通知，重组为完整帧，再发往本机 UDP；旧 8/13/20/21/32/33/37/40/48/64/72 通道固件也可使用同一工具。CSV 以 `vision-` 开头，包含 `received_at` 和实际通道字段，终端显示 B/DX、对齐状态、后距、完成记录及 IMU 角度误差和积分补偿。
无需蓝牙 COM 口，也不需要修改模块配置。当前转发仅接收遥测，不支持在线调参。

## 启动

先在手机 nRF Connect 点击 Disconnect，关闭 WHEELTEC APP，开启电脑蓝牙。
在源码仓库根目录打开终端，使用 Python 3.10 或更新版本：

```powershell
python -m pip install bleak
python tools/ble_vofa_bridge.py
```

默认设备名 WHEELTEC-IOS；有多个同名设备时用 `--address 蓝牙地址` 指定。
工具扫描后自动连接、订阅，断线后重新扫描。Ctrl+C 退出。
每次连接先用连续两帧确认通道数，确认后两帧一起转发；这会增加约一帧的起始等待，避免从新帧中途接入时误识别为旧 48/64 通道。之后逐帧转发。
依赖 API 见 [Bleak 官方文档](https://bleak.readthedocs.io/en/stable/api/client.html)。

## VOFA 配置

- 数据引擎：JustFloat。
- 数据接口：UDP（监听/服务器模式，如版本提供模式选项）。
- 本地监听地址：127.0.0.1 或 0.0.0.0；本地端口：9000。
- 若界面要求远端地址和端口，填写 127.0.0.1、9001。
- 打开接收。无需设置串口波特率，也无需发送启动指令。
- 当前 31 通道的波形时间步长可先设为 300 ms；以电脑实际接收时间为准。

转发器绑定本机 9001，发送到 VOFA 本机 9000；不能把两个程序都绑定 9000。
需要换端口时运行 `python tools/ble_vofa_bridge.py --port 其他VOFA端口 --local-port 其他源端口`。
当前43通道及单位见 [VOFA输出](VOFA跑图诊断.md)。CH6激光新鲜度、CH7后激光、CH8前激光（mm），CH11～18为IMU诊断，CH19～30为四轮目标、反馈与PWM；CH41锁定编号、CH42累计锁果次数。CSV保存全部43通道，转发器兼容原41通道固件。

## 排查

- 找不到设备：检查模块供电、电脑蓝牙，并释放手机或其他电脑的连接。
- RX=0：已订阅但没有通知，检查烧录版本、模块 UART 速率及 PD5 接线。
- RX 增长而 frames=0：没有解析到有效 8/48/64/72 通道完整帧，检查串口速率、丢包及所用固件。
- frames 持续增加而 VOFA 无曲线：检查 UDP 本地监听端口和 JustFloat 引擎。
- discarded 持续增加：存在非遥测字节或丢失片段；工具只转发通过帧长度及字段检查的数据。

自动测试：`python tests/vofa/test_ble_bridge.py`。该测试验证分片、噪声、缺失片段、连续帧和本机 UDP，不替代实际 BLE 稳定性测试。

USB自行前进复查新增CH31 LY、CH32 RX、CH33控制入口位掩码、CH34遥控速度原始设置；CH7后激光、CH8前激光不变，完整表见VOFA诊断文档。

视觉无输入诊断新增CH35接收字节、CH36坏帧、CH37串口错误，旧CH0～34保留。新转发器兼容旧35通道；需烧录38通道固件后才可读取这三项计数。

## 启动提示端口占用

录屏中的WinError 10048发生于转发器绑定本机UDP 9001，表示已有程序占用该源端口。2026-11-19本次已确认占用者是此前后台启动的同一路径转发器，并关闭释放。单文件EXE正常运行时可出现父子两个进程，不能仅凭进程数认定重复实例。

新版遇到端口占用时显示关闭已有转发器或改用`--local-port`的提示，不再打印未处理的异常堆栈；打包版保留提示窗口，按Enter关闭，也不会留下此次启动创建的空CSV。本次更新后不自动后台启动，用户双击一次即可。保留全部历史日志。

自动对齐后完整K任务击打已启用。成功返程后仍有有效绿色果则重新确认下一轮，新G=0立即退出；故障保护保留。VOFA追加CH38阶段、CH39最近成功区域、CH40成功次数，原CH0～37不变，需使用新版转发器。
