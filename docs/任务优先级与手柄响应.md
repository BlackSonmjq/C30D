# 任务优先级与手柄响应

当前遥控默认与单轴限速为 200 mm/s，Flash 旧值与手柄加速也受此上限约束。IMU 共用航向参数提高为 Kp=1.20、Kd=0.55、角速度限幅 ±0.50 rad/s。PS2/USB 持杆时连续 3 次新的 B=1 数据即自动接管树干对中，确认前保持手动，接管后忽略摇杆；完成后中心附近不反复抢占。任务分配方式与优先级保持不变。

优先级的默认分配集中在 `USER/task_priority.h`。FreeRTOS 数值越大优先级越高，当前配置范围 0～31，0 为 idle。遥控输入、IMU 采集和底盘控制默认同为 12，通过 `configUSE_TIME_SLICING=1` 的同级轮转及各自的延时/事件等待共享执行时间；tick 为 1 ms。USB 任务等待队列，底盘、经典 PS2 和 IMU 按 10 ms 周期阻塞，不在任务中永久占用 CPU。

已移除强制所有任务严格递增的预处理检查。`TASK_PRIORITY_CONTROL_GROUP` 可统一调整实时组，各角色默认值也支持编译时覆盖；代码不循环调用优先级设置 API，也不为维持某个任务领先而暂停调度。保留任务自身优先级是 FreeRTOS 分配执行时间所需的配置。

| FreeRTOS 优先级 | 任务 | 作用 |
| --- | --- | --- |
| 12 | `Balance_task` / 互斥的 `Check_task` | 100 Hz 编码器采样、底盘控制与 PWM，与遥控输入同级 |
| 11 | `vision_vofa` | 读取视觉快照、确认并提交击打任务、提交 VOFA 发送 |
| 12 | USB Host / 经典 PS2 | 采集手柄输入，与底盘共享同优先级轮转 |
| 12 | IMU | 采集姿态和角速度，供遥控时的旋转抑制使用 |
| 8 | `route_demo` | 50 Hz 路线状态机与速度命令 |
| 7 | `distance_task` | 机构测距反馈 |
| 6 | `stepper_task` | 步进机构协调与返程 |
| 5 | `servo_task` | 舵机动作、到位检查与重试 |
| 3 | `DATA_task` | CAN 发布、旧反馈、串口日志和机构调试 |
| 2 | `show_task` | OLED 显示 |
| 1 | `led_task` | 状态指示 |

未参与当前编译的旧推杆任务也统一到机构层 5。FreeRTOS 内核定时器等系统任务保留内核配置，不属于上表应用任务。

视觉接收仍在 USART3 的短中断内完成，没有增加图像识别计算。其 NVIC 抢占优先级为 0；USART2 遥测为 6。**NVIC 数值越小越优先，与 FreeRTOS 相反。** USART3 中断不调用 FreeRTOS API；USB、舵机等其他硬件中断保持原有设置。

`vision_vofa` 每 50 ms 检查发送时机，`ROUTE_VOFA_PERIOD_MS=271` 使实际发送周期预计约 300 ms。仍然只输出 32 个 float，加帧尾共 132 字节；原视觉 0～7 不变，转发器更换为 Load 版本。它已从混合 `DATA_task` 拆出，日志拥塞不再直接拖住视觉帧提交。当前自动击打关闭；启用后的区域映射和防重复逻辑保留在 [视觉击打](视觉击打.md)。

当前默认启用 [视觉对中](视觉对中.md)，直接在底盘的 100 Hz 自动控制分支运行，不新增任务。无需遥控器，上电初始化完成且底盘就绪后，使用新 B/DX 数据低速横移对中；到零、丢目标、超时等停车条件直接输出三轴零速。移动期间继续使用 IMU 航向抑制，不等待串口、机构或日志。对中与 VOFA 发送开关独立。

舵机命令仍由 DMA 连续发送，但不再在整帧发送期间调用 `vTaskSuspendAll()`。调用方在可抢占的有限轮询中等待，底盘、视觉、手柄等较高优先级任务可运行；并未将同步发送 API 改成异步 API。发送所有权持续到原调用方取走结果，防止 TC 中断完成后其他任务覆盖结果；忙碌时仍返回 `SERVO_BUSY`。

手动麦轮控制在前后或横向指令反向时，清除对应轴旧方向的平滑状态，再用原步长进入新方向，避免先沿旧方向持续若干控制周期。没有提高加速步长或轮速 PI 参数；路线的平移平滑逻辑保留。

遥控平移继续调用真实 `HeadingControl_HoldYaw`：进入手动时记录当前航向作为目标；IMU 测得偏航角误差或 Z 轴旋转速度后，输出反向纠偏角速度。摇杆只提供前后/横移，不提供主动自转命令。失能或姿态过期会输出零速并清除旧航向锁定，重新使能后重新锁定。`tests/chassis/test_manual_imu.py` 使用生产控制器验证了正负角速度阻尼、正负偏航纠正、限幅和失能/过期停车。

当前车头位于地图后方、车左对应地图右方，PS2/USB 手柄相对上一版再次反转两个平移轴：`forward = LY - 127`、`left = 127 - RX`。仍由左杆前后控制纵向、右杆左右控制横移；IMU 航向抑制及航模遥控器映射保持原值。

## USB 接收器等待与周期复位

旧 USB 枚举代码在 `ENUM_IDLE` 收到 BUSY 等待结果时累计 `testtime`，达到 500 次就调用 `NVIC_SystemReset()`，且计数不随新的连接过程清零。主控因此可能在接收器尚未初始化完成时反复复位，表现为 OLED 周期闪烁、手柄连接灯持续闪和视觉计数反复从较小值开始。现已移除该整机复位分支，BUSY 交由既有控制传输状态机处理；明确失败时仍保留 USB 的重试及 `HOST_ABORT_STATE`，不改变整车运行状态。

`tests/serial/test_usb_enumeration.py` 在旧固件中复现了复位请求，修复后的真实编译代码连续等待 600 次不复位，之后描述符成功会推进到下一枚举阶段，连续失败仍会按原规则退出。该测试不能证明某个实物接收器一定兼容，也不能代替供电、无线配对和实车枚举检查。

验证包含：真实编译固件的任务创建参数、USB 原生 FreeRTOS 优先级、USART2/3 NVIC 配置；舵机 DMA/TC/超时/并发所有权；完整 S2 收发、重试和错误恢复；手柄映射、反向首次输出与航向保持；视觉解析和接收中断。以上为编译和仿真，不是实车 CPU 占用或遥控延迟测量，实际响应仍需重新烧录后确认。
