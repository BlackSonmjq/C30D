# 视觉击打

当前固件默认关闭视觉自动击打（`VISION_STRIKE_ENABLE=0`），先执行 [视觉对中](视觉对中.md)，不会因视觉识别自动开启机构激光或提交 K 任务。下面保留启用击打后的行为说明：MaixCAM 负责识别并发送 `63 B DX G REGION 66`，STM32 根据有效 REGION 提交已有完整 K 任务。

| REGION | 原任务 | 执行机构 |
| --- | --- | --- |
| 1 | K1 | 1 号激光、左步进、1 号舵机 |
| 2 | K2 | 2 号激光、左步进、2 号舵机 |
| 3 | K3 | 3 号激光、右步进、3 号舵机 |
| 4 | K4 | 4 号激光、右步进、4 号舵机 |

启用击打时，`vision_vofa` 每 50 ms 读取一次视觉快照，B=1、G=1 且 REGION 1～4 同号连续确认 3 次后提交。仅有效帧计数发生变化才算新观察；相邻观察间隔达到 300 ms 会清除未完成确认。这里的次数指任务观察到的新快照，相机更快发送时不逐帧累计。击打模块不使用 DX；当前的独立对中模块使用 DX 控制横移。

启动条件沿用底盘就绪检查：麦轮车型、上电启动延时结束（当前约 10 秒）、电压至少 10 V、EN 使能且未停止；自检模式、步进任务忙、舵机任务或调试忙、导航已有作业预约时不接受新目标，也不缓存待执行任务。条件恢复后重新连续确认。

手动状态与原 K 命令相同，直接请求完整机构流程，遥控底盘仍由手柄控制。导航已接管时，通过原导航作业队列提交，由路线状态机停车确认后执行，完成后按原路线流程恢复。导航不允许作业时提交会被拒绝，仅在后续新视觉快照到来时重试。原 K1～K4 命令入口保留。

完整流程沿用原实现：选择对应激光 → 等待有效距离 → 步进接近距离阈值 → 舵机击打并回位 → 按实际前进脉冲返回 → 关闭激光。原距离阈值、脉冲限制、超时和失败处理不变。

提交成功后锁存本次目标。同一目标持续可见、REGION 改变或相机断流均不会解除锁存；任务及预约结束后，必须连续观察 3 次有效无目标快照（B/G 不同时为 1），才允许下一次目标确认。作业期间的无目标数据不用于重新使能，防止运动遮挡引发重复击打。

配置在 `USER/vision_strike.h`：`VISION_STRIKE_ENABLE` 当前默认 0；`VISION_STRIKE_CONFIRM_FRAMES` 和 `VISION_STRIKE_CLEAR_FRAMES` 默认 3，`VISION_STRIKE_MAX_GAP_MS` 默认 300。均支持编译时覆盖。视觉提交与 VOFA 开关独立；VOFA 当前为 32 通道（原 0～19 保留，20～31 增加四轮目标/反馈/PWM），须使用 Load 版转发器。

视觉接收中断只解析字节，任务中只做确认和提交，不等待机构动作、不输出日志、不暂停调度。遥控、底盘及 IMU 默认同级 12，视觉任务 11；机构仍由原任务执行。

本地验证使用 `python tests/camera/run_vision_strike_tests.py`，对真实解析器、确认逻辑和从生产代码提取的提交函数做 ARM 仿真，覆盖四个映射、重复快照、抖动、断流、忙碌、导航预约、提交拒绝重试和时间回绕。编译及仿真不能代替实机区域与机构动作核对。
